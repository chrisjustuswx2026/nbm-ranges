Briefing playbook (full version: BRIEFING-PLAYBOOK.md)

Who writes what: the dashboard writes the routine briefings (new SPC risk, storms organizing, watch, new outlook) in the team's voice: "The SDR Weather Intelligence Division is tracking… We're leaning toward… / A good chance of… / Expect… / Plan on…" (firmer as the odds climb). Never name the agencies to clients. The team writes the judgment briefings: model trends, hurricane and snow signals, seasonal. Push: open the briefing → Copy link → paste in the Baron push; each person opens their own dashboard.

  • Six parts, always in this order: headline (the story, ~8 words) → intro paragraph (what, where, when, how sure; name the client's place) → one map with the site dot, a key and a source caption → 3–5 detail bullets with bold labels → outro paragraph (what it does and doesn't mean, when we update) → bottom line (what to do, in operations language).
  • Severe: main threat with numbers · timing at the site · rain range · lightning · model agreement x/5. Timing strip ("STORM WINDOW · SAT 3–7 PM"). Outro: not every spot sees a severe storm on a level 2 day; updates by noon and when a watch is issued.
  • Outlook (CPC): all four maps written up together. Temperatures and rain with odds words (60%+ strong odds · 50%+ good odds · 40%+ leaning · under 40% slight lean) plus NOAA normals for the site. Outro: warmer than normal doesn't mean every day is warm; wetter is the total, not rain every day.
  • Tropical: each area's 7-day chance and likely track · what it means for the client · what's typical this late in the season.
  • Seasonal / monthly: odds · normals from start to end of month · first frost or snow · normal rain total · the holiday/big-event week. Outro: outlooks set the odds; the 10-day is for planning.
  • Automatic briefings fire only on official changes at the site (SPC day 1–3, mesoscale discussion, watch, CPC flip). Max 3 a day; each expires with its trigger. Team briefings never expire and always win.
  • Links: "Copy link" on every briefing. ?brief=latest, ?brief=severe / outlook / tropical / seasonal. Paste it as the URL in the Baron push; it opens in Safari. Production: one short link per kind that routes each signed-in client to their own dashboard.
  • Working examples: the Clemson live file → Briefings → the three "sample" briefings.

Status engine (same three words as the channel)

  • TAKE ACTION (red): a Tornado, Severe Thunderstorm, Flash Flood, Hurricane or Extreme Wind Warning polygon covers the site, or a lightning strike inside the site's policy radius (default 10 mi) in the last 30 min. A meteorologist can force it.
  • HEADS UP (yellow): a Watch, Advisory or Special Weather Statement for the site (SWS gets a polygon on the radar, a box in the list, and a line in the crawl, same as the channel); 60%+ precip inside the next 3 hours (the go/no-go window) (the channel uses 40% in 12 h, 60% in summer, for its look-ahead; the dashboard deliberately does not); a warning polygon within 30 mi; or lightning within 30 mi. The line says what and when.
  • ALL CLEAR (green): none of the above. The line says how long it stays quiet and what follows.

Lightning rule

  • Any strike inside the policy radius starts a 30-minute all-clear clock. Every new strike inside the radius restarts it. When it runs out, the call returns to the forecast-based state.
  • Policy radius and hold length are per site (policyMi, holdMin). Defaults: 10 mi, 30 min. Rings on the map are drawn from the same two numbers: red = policy radius, grey = heads-up radius (30 mi).
  • The page never calls the lightning vendor. The server runs one regional query a minute for the whole footprint, only while convection is possible, and answers each site with strikes within 50 mi in the last 30 min. The page's hook is LTG.feed() → [{lat, lon, time}].

Alert polygons

  • Every warning, watch, advisory and SWS near the site is drawn on the radar in its color and listed under it. Tap a polygon or a row for: expiration, hazard line, threat tags (wind, hail, damage threat), OBSERVED / CONFIRMED vs RADAR INDICATED (from the NWS tornadoDetection / flashFloodDetection parameters and the SOURCE line), and a purple PDS tag for particularly dangerous situations, destructive tags and emergencies.

Radar rules (same as the 24/7 channel)

  • Loop frames: Iowa State NEXRAD nexrad-n0q-900913 (−55 … −5 min). Newest frame: NOAA MRMS from mapservices.weather.noaa.gov/…/radar_base_reflectivity/MapServer/export (EPSG:3857 bbox, png32, transparent, 512 tile). Falls back to the current NEXRAD frame if MRMS fails.
  • Smoothing setting RADAR.smooth: 0 raw · 1 light (native tiles to z7) · 2 medium, default (z6) · 3 heavy (z5). Past that zoom the browser stretches tiles with bilinear blending. MRMS requests 256 px on a 512 tile at 2+. (MapLibre in production: raster-resampling: "linear" plus the same source maxzoom.)
  • Timing: 450 ms per frame, 1.6 s hold on the newest, all tiles refreshed every 2 minutes. Play/pause button.
  • SPC mesoscale discussions: polled every 2 min from spc_mesoscale_discussion/MapServer/0/query (GeoJSON), "NoArea" ignored, orange outline #FF8C1A with light fill, labeled "SPC IS WATCHING · MD #____".
  • Smoothing softens edges but won't match Baron's painted contours exactly; that needs a licensed Baron or Xweather radar feed.

UV index

  • NWS has no UV in its grid. The prototype uses Open-Meteo (free, no key, hourly uv_index and daily uv_index_max); its free tier is non-commercial, so production either takes Open-Meteo's paid API plan or EPA's UV forecast by ZIP (data.epa.gov/efservice/getEnvirofactsUVHOURLY/ZIP/{zip}/JSON, free, next ~20 hours only). Shown in the hourly detail (daytime), on every 7-day day as a chip, and in today's conditions.

Lightning data: where to get it

  • First call: Baron. The app already licenses Baron; ask whether the Baron Weather API lightning products (and their terms) cover a web dashboard. If yes, zero new vendors. Pricing is by quote.
  • Fallback: Xweather (Vaisala) Lightning API. Strike-level data within seconds of detection, cloud-to-ground and in-cloud, queries by point + radius or bounding box, plus /lightning/threats polygons and webhooks that push new strikes to a URL (so the server may not need to poll at all). Pay-as-you-go: 15,000 free accesses a month, then $0.0006 per access with a 10x lightning multiplier ≈ $0.006 per lightning request. One regional query a minute during active weather ≈ $0.36/hour, flat regardless of site count.
  • Also worth a look: AEM / Earth Networks Total Lightning Network (the network behind many pro apps; API by quote, strong in-cloud detection, good for early warning). Allisonhouse resells Earth Networks lightning for display use but its license is for personal/single-app display, not a client product.
  • Not for this: Blitzortung (community network) is non-commercial; NWS/NOAA publish no real-time strike feed.
  • Whatever the source, the page contract stays the same: LTG.feed() → [{lat, lon, time}], strikes within 50 mi in the last 30 min. Andrew, if you have a better route (a feed you already use, Baron's push), take it; only the contract matters.

Crawl

  • Default content is the site's own forecast (tonight, tomorrow, then the 7-day). Alerts near the site (polygon within 100 mi, or the site's own) go first and take precedence; alerts elsewhere in the footprint never ride this crawl. The channel's crawl stays Southeast-wide; this one is per site.

Audio

  • Same tones as the channel: warnings and lightning holds get the hard four-burst alarm; watches a double chime; advisories, SWS and lightning within 30 mi a single chime. Plays once per state change, never on load. Browsers require one tap before any audio, so the 🔊 toggle in the top bar arms it and remembers the choice. Production: the app can play without the tap.

Map look (matches WeatherFront and the channel)

  • Land #878787, water #405170, county lines #3D3D3D thin, state lines #000000, city labels white with a black edge. Mexico, Canada, Cuba and the Bahamas are land. Panels stay navy; only the map is gray.
  • Alert polygons use the weather.gov hazard color table by event name (fallback #8A9BB8). Warnings: fill 0.34, 3.5 px outline, 2.2 s pulse. Everything else: fill 0.14, 1.5 px, steady. The legend lists only the types on the map.
  • Every Special Weather Statement is HEADS UP, and its line says what it's about (NWSheadline → HAZARD line → first sentence, shortened to the hazard, ~34 chars).

Basemap

  • No tile vendor, no key. State and county outlines are US Census files shipped with the page (same files as the channel), drawn over the dark ground; the NEXRAD mosaic rides on top. CARTO and others now require keys, so they are out.

Polygon pulse

  • Warning outlines pulse slowly (stroke opacity 1 → 0.35 → 1 over ~2.2 s). Watches, advisories and SWS stay steady so warnings stand out. Honors prefers-reduced-motion. Channel (MapLibre): in a requestAnimationFrame loop, map.setPaintProperty("warn-line","line-opacity", 0.675 + 0.325*Math.sin(t/350)).

Data

  • Free from NWS: conditions (nearest station), hourly, 7-day, alerts by point and by state, warning polygons. Radar: the channel's map engine (NEXRAD mosaic on our dark basemap), per site, with nearby towns from the city list.
  • Lightning: Baron if the license covers the web dashboard, otherwise Xweather lightning (10x access multiplier, about $0.006 per request).
  • WBGT shows only when feels-like ≥ 80°. Wind always shows gusts. Feels-like is heat index or wind chill, whichever applies.

24/7 channel embed (YouTube Live)

  • Desktop tile and Watch Live use one embed: youtube-nocookie.com/embed/live_stream?channel=UC…&autoplay=1&mute=1. It always shows whatever the channel is streaming, so the link never changes between streams. Autoplay only works muted (browser rule); viewers unmute with the player's speaker button. Set CHANNEL.youtubeChannelId once.
  • Stream setup that keeps it working: stream from OBS with the channel's default stream key (YouTube Studio → Go Live → Stream), "Allow embedding" on, "Made for kids" off, latency Normal, DVR on; OBS → Settings → Advanced → Automatically reconnect on. If the stream drops, the embed shows "offline" and picks the stream back up when it returns.
  • Production check: a server job calls the YouTube Data API (search?channelId=…&eventType=live&type=video) every few minutes and alerts us if nothing is live.

Tap a city: this week in red / yellow / green

  • Red only from an active NWS warning covering that day (warnings can't be forecast). Yellow: an active watch / advisory / SWS covering that day, or that day's NWS forecast has rain ≥ 40% (≥ 60% Jun–Sep), thunder ≥ 30%, gusts ≥ 35 mph, frost/freeze, snow/sleet/ice, a high ≥ 97°, or an SPC Slight-or-higher risk over the city (days 1–3). Green otherwise. Forecast = NWS 7-day text per city (2 calls, cached 30 min), only when someone taps.

  • Reliability: page reloads itself if no radar imagery arrives for 15 minutes; fresh restart every 6 hours, only when the call is ALL CLEAR. The error line names what failed (alerts, hourly, observations…).
  • Brand: on-screen brand is "SDR Weather Intelligence" only.
  • Channel-only for now: takeover zooms and cool-downs, the Active Alerts board, tropical (NHC) pages, WPC/CPC charts, GIBS satellite frames. Strips (BAM logic)

  • Rounding everywhere: precip and thunder to the nearest 10% (anything under 10% shows nothing), humidity to 5%, clouds to 10%.
  • Hourly: every hour the NWS grid covers (about 7 days). Each midnight gets a vertical day marker (TOMORROW, WEDNESDAY…), the first hour of each day carries a small day tag, and the header shows the day currently at the left edge as you scroll. Visible: time, icon, temp, precip %, wind and gust. 12H / 72H / ALL control. Tap an hour: precip, thunder %, rainfall, snow, feels-like, WBGT (est), dew point, humidity, wind, gust, clouds, visibility. Sources: forecastHourly + forecastGridData (apparentTemperature, dewpoint, relativeHumidity, skyCover, windGust, quantitativePrecipitation, snowfallAmount, probabilityOfThunder, visibility).
  • 7-day: visible = day, icon, low (offset left) / high, precip %, wind and max gust. Winds rounded to the nearest 5 mph ("SW 5–10"), gusts rounded up to 5 and shown only at 15+. UV only in the tapped-day detail, colored by level. Tap a day: day/night precip, rainfall total, thunder, max gust, humidity, clouds, WBGT peak (when high ≥ 75), snow, and the NWS day and night text.
  • Confidence: not shown. It can't be derived honestly from one deterministic feed. Two real routes: (1) the meteorologist sets it in the briefing (now); (2) Andrew computes it server-side from NBM percentiles (10th/50th/90th for temp, gust, QPF) and ships it with the site's forecast. Until then, no number.

Video rule

  • The briefing shows the latest video only if it was posted within the last 24 hours. Older than that, the video box reads "No video necessary at this time." Set window.VIDEO = { postedAt, label, url } when a video goes up; the page checks the age every minute.

Forecast ranges · National Blend of Models (free, NOAA)

  • Hourly/daily detail shows Min / Likely / Max for rain, snow and ice = NBM 10th / 50th / 90th percentile. Source: NBM v4 probabilistic text bulletins (NBP, station-based, plain text) or the NBM GRIB2 percentile fields on NOAA's AWS bucket for any point.
  • NOAA's servers don't let a web page pull these directly, so a small scheduled relay (a Cloudflare Worker on the same account as the Pages site) fetches every hour after each NBM run, keeps only our client points, and serves a tiny JSON: { day, rain:[p10,p50,p90], snow:[…], ice:[…] }.
  • Confidence comes from the spread: tight spread = high, wide = low, shown 1–5 next to the range. Never invented when the data is missing.

Lightning · Xweather (decided)

  • Endpoint: data.api.xweather.com/lightning/closest?p=LAT,LON&radius=50mi&limit=1000 with client_id / client_secret. Fields used: loc.lat, loc.long, ob.timestamp, ob.pulse.type (CG / IC).
  • Standard access only returns the last 5 minutes and counts each call 10x. So the relay polls once a minute, stores strikes for 30 minutes, and every dashboard reads from the relay, never from Xweather. Keys stay on the server.
  • Relay answers LTG.feed() with [{lat, lon, time, type}]; the 10-mile / 30-minute clock and the 10 + 30 mile rings are already built to take it.
  • Cost grows with client sites, not viewers. Ask Xweather about the Lightning Enterprise add-on (1x instead of 10x, 24-hour history, polygon queries) once there are 10+ sites.

Farm clients only · extra data pack

  • Shown only when the client is tagged farm (Turf Mtn-type). Stadiums, counties and restaurants never see it.
  • Spray window (Good / Caution / No): wind 3–10 mph, no rain for 4+ hours after, Delta T 2–8 °C, calm clear nights = caution (inversion).
  • Delta T = air temp − wet-bulb temp, from NWS temperature + dew point. GDU = ((high + low) / 2) − 50 °F, highs capped at 86, lows floored at 50. Both free.
  • ET rate and soil temperature need extra sources (state ag mesonet stations, or model fields through the relay). This is the bigger step; it waits until the first farm client signs.

Chat (see CHAT-PLAYBOOK.md)

  • Team side opens a context panel for the asking client automatically: their schedule, status, active NWS alerts, SPC MD / watch / outlook level for that day, rain chance + timing, range, model agreement, lightning. Urgent items at the top and said first.
